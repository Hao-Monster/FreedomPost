# 商城订单转客服流程详细设计

## 目标

商城订单创建成功后，不再在订单弹窗中直接展示客服二维码。用户先获得服务端生成的订单号，再进入 Chatwoot 客服，把订单号和商品信息发送给客服；客服确认后通过 Chatwoot 回复对应的微信二维码，并提示“如果客服回复不及时，请拨打微信电话联系”。

## 本期范围

- 保留现有 `POST /api/orders` 服务端订单创建、服务端定价、库存和幂等约束。
- 修改商城下单成功态，展示订单号、客服入口和微信电话兜底提示。
- 生成待发送消息：订单号、商品名称和人工处理请求。
- 优先复制消息并尝试打开 Chatwoot；浏览器拦截弹窗时提供可重复点击的明确按钮。
- 移除商城订单成功态中的静态微信和 QQ 二维码。
- 更新生产站点 CSP，允许 Chatwoot SDK、API 和 WebSocket。

## 非本期范围

- 不修改订单表结构、价格计算、库存扣减或订单状态接口。
- 不由前端直接修改订单状态或确认付款。
- 不自动发送 Chatwoot 消息；用户必须在客服窗口确认并发送，避免误发和重复会话。
- 不改变付费文章订单和账户订单流程。

## 流程

1. 用户提交商城订单。
2. API 按现有规则创建订单并返回 `orderCode`、`productTitle` 等字段。
3. 页面显示订单号和客服入口。
4. 页面生成待发送文本并复制到剪贴板，尝试打开 `support-freedompost.openal.uk`。
5. 用户在 Chatwoot 中粘贴并发送文本。
6. 客服按订单号在后台核验后回复二维码及微信电话提示。

## 安全与失败策略

- 订单号和商品名称均来自服务端响应，并通过现有 HTML 转义函数渲染。
- 不接受客户端价格、商品 ID 或订单状态作为可信数据。
- 剪贴板不可用时不伪造成功状态，用户仍可复制页面订单号后手动进入客服。
- 弹窗被拦截时显示重试提示，订单不会丢失。
- 客服域名使用固定 HTTPS 地址，不从 URL 参数拼接目标地址。

## 验收标准

- Given 订单 API 成功返回订单，When 下单弹窗完成渲染，Then 页面显示订单号、商品上下文和客服入口，不显示旧的微信/QQ 二维码。
- Given 浏览器允许剪贴板和弹窗，When 订单创建完成，Then 待发送文本被复制并打开 Chatwoot。
- Given 浏览器拦截弹窗或拒绝剪贴板，When 用户点击客服按钮，Then 页面显示可理解的失败提示且订单号仍可见。
- Given 生产构建，When 访问首页和文章页，Then Chatwoot widget 继续加载，CSP 不阻断 SDK、API 或 WebSocket。
- Existing order API, pricing, inventory, affiliate and paid article tests remain passing.
